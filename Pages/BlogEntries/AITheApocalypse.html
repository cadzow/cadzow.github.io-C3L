AI - The Apocalypse or not?

By Scott Cadzow

Machines are amazing at processing information and performing tasks at a speed and accuracy that surpasses human capabilities. They can sift through data and find patterns that a human analyst may miss. They can be tasked to find artefacts that have very low probability of existing (so low that a human would never spend time looking) and actually find them.

So all that data or information that the machines process is generally referered to as its knowledge base when it comes to AI. So when that knowledge base is code (programs) and the machine is asked to find vulnerabilities it will find them. This is all possible by patterns and pattern recognition. so we know what kind of thing to look for to leak memory, bypass boundary checks, and we feed those patterns into the machine with a broad instruction of "find something like this in that" and away it goes and does that. The problem that we're facing is that we've spent decades being really bad at writing code and in a hybrid mix of incompetence and laziness, of "good enough" code, we're suddenly getting the most stringent code review ever and we're being found out. Generally our code is 100% guaranteed to be buggy. Every bug is a path to exploitation.

If we assert that AI, certainly in ML form, is a fast data collation tool can it make meaningful inroads to identifying causation and thus make sense of data?
